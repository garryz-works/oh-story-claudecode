# Agent Note: 按五步精修整理短篇三个 Skill 的执行资料

Status: implemented
Related: [短篇资料合并](2026-10-14-consolidate-short-writing-references.md)、[短篇按作者时刻加载](../architecture/2026-09-26-short-write-by-moment.md)

## Problem

短篇扫榜、拆文、写作的 66 份入口与参考资料仍有短碎指令、重复元说明、指代不清和无来源精确统计。部分旧条款与当前契约冲突，例如短篇召回使用长篇设定路径、可选反转被写成必选、源文观察混入写作命令。用户要求安装并严格按 prose-gap-polish 的流程和规范整理全部文本。

## Decision

#469 与 #470 已合并，prose-gap-polish 从 `zenstory-ai/.github` 安装至本机技能目录。短篇写作 37 份、拆文 23 份、扫榜 6 份资料均逐份按合句与措辞、去冗余、消歧义、回查事实补信息、修逻辑五步审查；清晰且无断点的段落保留，真实引文、代码示例、机器字段、编号、产物格式与必要门禁保持。

- 短篇多对标从 `设定.md`「对标摘要」衔接，构思与正文的无反转、无反派、可选道具范围一致；作者表达与题材例外沿用既有文风裁决。
- 拆文按源文证据观察人物、关系与技法，节点按文本出现顺序排列；Stage 6 内容写完并通过验收后，才将 `6` 加入完成数组。覆盖率分母使用全文识别出的关键变化。
- 扫榜按采集脚本实际提供的字段解释指标，区分简介与正文、单期与趋势、排名与质量；历史资料只给待验证候选，无样本依据的精确比例删除。
- 共享资料从 canonical source 修改并同步副本，不提高加载预算，不扩充工作流。受影响的八个 ClawHub 包更新显式版本，入口的精确依赖同步更新，包指纹由仓库固定的发布工具重新锁定。

## Alternatives considered

- 只统一标点和替换词语，改动小且容易校验；但无法修复用户明确要求处理的信息和逻辑断点，因此不采用。
- 为短篇另复制一套共享记忆、文风和对话资料，能隔离其他 Skill；但会增加重复规则及维护成本，因此仍从共享真源修改。

## Consequences

收益是三条短篇流程的文字与当前产物、脚本契约一致，减少重复说明和误用旧理论的机会。66 份资料中实际修改 60 份，合计减少 5,450 个非空白字符。代价是共享真源的措辞调整会同步到其他消费者，需要同时验证字节一致性、引用、预算和适配层；示例材料无法支持的判断只删去或缩小范围，不补造事实。

静态检查、工作流编号、文档预算、共享文件、当前契约、写前引用门禁、作者报告和笔记检查均通过；共享 reference、构思与交付契约、作者记忆、文风优先级及扫榜聚合回归通过。story-setup 部署和 Codex / OpenCode / Antigravity / OpenClaw 适配检查通过。固定的 ClawHub 0.23.3 CLI 离线验证全部 13 个 manifest 条目，确认本次包内容与版本锁一致。
